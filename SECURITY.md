# Local development security

RelayDesk v0.3 is a single-user local prototype. It binds to `127.0.0.1`, validates HTTP Host and Origin, and provides no public authentication or remote deployment configuration. Do not expose its port through a tunnel or reverse proxy before adding device/user authentication and reviewed authorization.

Default execution adapters and the work inbox are simulations. The inbox only loads synthetic fixtures and records mock delivery outcomes; it has no WeChat, QQ, dot, or other external messaging connection. The explicitly enabled Codex adapter launches a configured official CLI directly (no shell), with fixed arguments and a fixed project working directory. It sends the selected conversation history through stdin and uses the CLI's normal ChatGPT login. It does not read or copy credentials or accept executable paths, model names, environment variables, or extra arguments over HTTP. Other providers and real message connectors remain unimplemented.

Incoming channel messages are untrusted data, never execution instructions or reply authorization. Preparing a reply binds an immutable account, native thread identifier, source message, and exact content without sending it. A separate explicit send intent is required; demo high-impact or sensitive cases also require review confirmation. Those demonstration rules are not a complete sensitive-data classifier. Idempotency keys and duplicate payload detection prevent repeated delivery; a pending or unknown result blocks another send for that source message even with a new key. A restart converts unconfirmed sending states to unknown. This prototype provides no automatic retry or unknown-result override. Real integration requires native identity and delivery evidence, not contact-name matching or a screenshot of a chat list.

The Codex adapter disables shell, plugins, browser and related capabilities and requests a read-only sandbox. These controls are not a complete file-read isolation boundary. It is restricted to a trusted local operator; do not forward untrusted channel content or expose this API remotely. Terminal authentication/compatibility errors fail closed without API-key fallback, automatic login, update, or application-level resubmission. Nonterminal CLI diagnostics are allowed to reach a bounded final result; any CLI transport retries share that same timeout. Output limits, timeouts and process-exit confirmation constrain the subprocess lifecycle. Raw provider diagnostics are not returned to the browser.

Adapter startup probes the configured executable's version with the same environment allowlist and bounded time/output. Only the reviewed versions 0.142.2 and 0.162.1 are accepted. Version 0.162.1 additionally receives `agents.enabled=false`, alongside disabled multi-agent features; that config key is not accepted by the older strict schema. Unknown or failed version probes stop startup without publishing raw diagnostics. Version acceptance is not proof of model access or complete isolation.

A detached CLI may survive an abrupt server crash. Interrupted real tasks and unconfirmed stops quarantine real execution across restarts. After manually verifying the old process has stopped, the local operator may acknowledge that check with `RELAYDESK_CODEX_ACK_INTERRUPTED=1` for one startup; never leave that acknowledgement permanently enabled. No HTTP route can acknowledge it, and stored PIDs are not used to kill processes. Persistent storage failures stop active execution, reject further writes, and require storage repair followed by restart; an in-memory status is not a guarantee it was saved.

Conversation data is stored unencrypted in `.data/` on the local machine. Protect it using your operating system's permissions and disk encryption. Do not upload that folder, `.env`, logs, or real message samples. This repository only includes synthetic test inputs and a secret-free `.env.example`.

Remote integration needs explicit identity, scoped device pairing, transport encryption, replay protection, rate and storage limits, audit retention, and exact-action approvals. A local demo approval must not be reused as approval for future external actions.

To report a vulnerability, use the repository's private vulnerability reporting feature if enabled. Do not put secrets or private conversation data into public issues.
