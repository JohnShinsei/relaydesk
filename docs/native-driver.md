# Codex App Server のローカル接続

公式 Codex CLI **0.162.1** の App Server を、非公開の stdio JSON-RPC で利用します。モデル実行、公式ログイン、ネイティブ会話の保存は公式 CLI に任せます。RelayDesk の `EngineDriver` は、会話の対応付け、承認の表示、状態の保存と復旧だけを担当します。第三者の harness はインストールしていません。MIT / Apache-2.0 のクライアントを設計上の参考として調査し、コードのコピー・改変は行っていません。

## 起動

公式 CLI と通常の ChatGPT ログインが利用できる環境で、リポジトリのルートから実行します。CLI のインストールやログイン処理は自動で行いません。

```sh
RELAYDESK_ENABLE_CODEX_APP_SERVER=1 \
RELAYDESK_CODEX_PATH="$PWD/.tools/node_modules/.bin/codex" \
RELAYDESK_CODEX_MODEL="gpt-6-astra" \
npm start
```

既定では実行環境へのアクセスを無効にします。ローカルの操作者がファイル操作の承認を検証する場合に限り、`RELAYDESK_CODEX_NATIVE_ENVIRONMENT=1` を追加できます。作業場所は `.data/codex-native-workspace` に固定され、サンドボックスは `read-only`、承認は `on-request`、審査者は `user` のままです。シェル・ブラウザー・プラグインは無効です。**承認すると、その操作に限って書き込みが許可される場合があります。** 固定ディレクトリやサンドボックスは、すべての読み取り範囲を隔離するものではありません。

旧 `RELAYDESK_ENABLE_CODEX=1` は独立した exec テキストアダプターです。画面でも旧モードと表示し、ネイティブの承認・再開には使いません。

## 起動時の確認

App Server には exec の `--ignore-user-config` に相当するオプションがないため、空の設定表で既存の接続が消えたとは判断しません。

1. 公式 provider と endpoint、承認、サンドボックス、無効にする機能を起動引数で固定します。
2. 会話を作る前に `initialize` と `config/read` を行い、有効な制限と MCP の名前だけをメモリ内で確認します。設定の全文・認証情報はログ、データベース、画面に保存しません。
3. MCP があれば探索用プロセスの終了を確認し、接続ごとの `enabled=false` を引数に加えた新しいプロセスを起動します。再確認で未無効の接続や新しい接続があれば、会話を開始しません。CLI のキー構文で安全に指定できない名前も拒否します。

グローバル設定は変更しません。0.162.1 のソースで確認した制限用の内部環境変数で遠隔制御の復元を止め、実際の状態通知が `disabled` であることも確認します。この内部仕様を将来のバージョンにそのまま適用せず、未確認の CLI バージョンは拒否します。自動ログインのブラウザー起動も抑制します。これは信頼できる本機操作者向けの確認であり、未知の管理ポリシーや外部プロセスによる同時設定変更まで隔離する保証ではありません。

## 承認と復旧

会話 ID を保存してから新しいターンを開始し、次の入力では同じ公式スレッドを再開します。過去のローカル履歴を再送せず、新しい入力だけを渡します。各処理は専用の stdio プロセスを使用し、OS の常駐 daemon はインストールしません。

承認は固定のリクエスト ID、スレッド、ターン、操作項目に結び付けます。操作と差分が不完全、対象が範囲外、追加権限を含む場合は「批准一次」を表示しません。承認・拒否の送信前に意思決定を保存し、送信結果が不明なら再送せず `unknown` とします。承認要求が撤回された通知だけでは、実行成功と判断しません。

中断の応答は停止完了を意味しません。ネイティブの `turn/completed` を受信して初めて完了・中止・失敗を確定します。切断や再起動後に結果が不明なら、新しいタスクを止め、保存済みの正確なターンを読み取って照合します。照合は新たなモデル実行ではありません。ターン ID がない、別のターンしか見つからない、終態が不明な場合は隔離を維持します。旧 exec 用の `ACK_INTERRUPTED` では解除できません。

SSE の再接続では保存済みの完全な状態を取得します。メッセージはネイティブの項目 ID で更新し、イベントを再実行しません。実動作を確認した範囲と未確認の範囲は [検証記録](verification.md)を参照してください。
