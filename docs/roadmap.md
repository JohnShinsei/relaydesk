# 第一版路线图

目标是人在国内，稳定地把任务交给日本 Windows 电脑，并能确认结果、审批和停止。按可检查的闭环推进，不以安装成功、截图或接口存在代替验收。

## 0. 本地重整：当前范围

- 保留 SQLite、SSE、Codex 与演示数据，仍是单个 RelayDesk 服务。
- 提供方中立执行器接口与默认关闭的 Hermes loopback HTTP 驱动。
- 主界面聚焦任务、状态、结果和下一步；微信收件箱为次要演示。
- 离线检查 ID、重复提交、停止、审批和未知结果，并执行 `npm run check`。

此阶段不启动真实 Hermes API，不调用真实模型，不安装后台服务，不做公网部署。自动化通过只代表覆盖的本地行为通过。

## 1. 日本电脑上的真实文件闭环

操作者配置独立 API key、指定测试目录与工具权限。先备份数据，再执行无害文件任务。保存版本、task/session/run ID、实际文件与终态证据，并检查：

1. 认证或能力探测失败时保持不可用，配置和凭据不返回浏览器。
2. 输出文件内容符合预期，任务与原生 ID 能持续对应。
3. 相同提交不重复执行，同 key 不同正文被拒绝。
4. 先验收受支持工具的一次批准与拒绝；文件编辑审批目前保持关闭，须补全差异预览与精确绑定后，才验收拒绝无修改、批准仅所列修改以及重复 / 过期批准不生效。
5. 停止先显示处理中，工作退出才确认；晚到的完成结果按实际终态显示。
6. 浏览器重连、RelayDesk 重启后查询同一 run，不重新发送 prompt。
7. 创建响应丢失、run 不存在或上游重启 unknown 时，保留待确认并阻止后续真实任务。

任一结果不确定、身份无法对应、重复副作用或凭据泄漏，停在该项；禁止新建任务来掩盖问题。缺少 run ID 的人工核对与解锁流程尚需设计。

## 2. 远程认证与跨境闭环

先选择国内实际可用的路径；需要时增加仅转发的 Hub，日本端连接仍放在同一服务中。凭据留在日本。

上线前实现并验证身份验证、加密、访问撤销、重放防护、限流、审计与备份恢复。Host/Origin 校验不是远程认证。

国内真实网络验收“提交文件任务 → 中途断网 → 重连查询原任务 → 获得同一结果”。确认重新登录不重复提交，撤销后不能继续控制，代理不把 SSE 缓冲成假在线。文件下载须另行实现受控 artifact ID、范围校验和授权，不开放任意路径读取。

## 3. Windows 桌面与常驻

文件闭环通过后，逐项加入软件、必要截图和桌面操作。明确用户会话、权限提升、锁屏、休眠、重启、开机自启与自动恢复的实际限制。

保持桌面任务串行，测试与本机人工操作竞争的行为。无人值守、锁屏可操作或重启自动继续，必须有真实证据才承诺；终端测试不替代桌面验收。

## 后置范围

多设备、并行真实任务、复杂 Hub 调度、微信自动收发、邮件、自动对外发送、语音、多模型编排和永久审批不进入当前主流程。需要时重新定义权限、稳定身份和验收标准。

本轮结果以实际检查为准。旧 `docs/verification.md` 保留原先 Codex / macOS 历史记录，不迁移为新架构的 passed。
