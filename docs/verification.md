## 官方 CLI 与真实链路探测

- 桌面应用附带 Codex CLI `0.142.2`；`login status` 显示 `Logged in using ChatGPT`。没有打开或复制认证文件。
- 在固定空工作目录、只读沙箱、关闭已核验的 shell/插件/浏览器等能力、无 API key 回退条件下进行合成文本探测。默认 `gpt-5.4`、显式 `gpt-6.1-sol` 及本机 model/list 列出的 `gpt-5.3-codex` 均被官方服务以 HTTP 400「该模型不支持当前 ChatGPT 登录」拒绝，没有助手消息。
- CLI 另报告模型缓存解析缺少 `base_instructions`。这提示版本/模型元数据可能不一致，但尚未证明根因。`model/list` 的模型名不等于账户可用性保证。
- 后续只读 `config/read` 核验到本机有效模型为 `gpt-6-astra`，reasoning effort 为 `ultra`，没有显式 provider 覆盖；适配器使用 `--ignore-user-config`，因此该默认设置不会自动生效。`model/list` 无下一页，仍返回 `gpt-5.4`（默认）、`gpt-5.4-mini`、`gpt-5.3-codex`、`gpt-5.2`。没有读取或输出完整配置及认证信息。
- 以 `--model gpt-6-astra` 经正式适配器复测，CLI 在助手输出前发出 `item.completed` / `item.type=error`，明确提示该模型元数据未找到、将使用 fallback metadata。适配器停止；本次没有取得该模型的官方推理成功或拒绝结论。已修正把此类 CLI 诊断误标为工具事件的问题，继续以模型元数据错误安全失败。

## 已知边界

- Node.js 要求 24.15+（24 LTS）或 26+，本轮运行环境是 26.3.0，未跨版本/跨系统验证。
- 真实模型成功响应、订阅额度兼容性、工具审批和厂商任务取消尚未通过 RelayDesk 验证。CLI 存在、显示已登录或已配置都不代表模型接通。
- 固定目录和只读沙箱不等于完整文件读取隔离；当前真实适配器只面向可信本机操作者。不得直接接收不可信消息渠道或暴露给远程用户。
- 手机界面适配与手机远程接入是两回事；当前没有 VPS、TLS、用户认证、设备配对或公网入口。
- 未监听微信、QQ、Slack、邮箱；未发送消息。未下载或运行语音权重。
- SSE 按会话发完整快照、SQLite 按会话保存 JSON；适合小规模本地原型，尚未做大历史量、并发负载或实时性能基准。
