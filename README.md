# RelayDesk

複数の AI との会話と、ユーザーの確認を経て進めるタスクをまとめるローカルワークスペースです。

将来的には、自分で管理するサーバーを経由して、スマートフォンから Mac 上の実行エージェントに接続することを目指しています。**v0.3 はローカル環境向けの試作版です。模擬チャット、架空の業務メッセージを使った受信箱、明示的に有効にする公式 Codex App Server 接続を利用できます。実際のサービスとの接続状況は、以下を参照してください。**

メッセージの振り分け、元メッセージとの関連付け、送信確認、重複送信の防止はバックエンドで処理します。Web 画面は現在のローカル検証用の入口です。今後、接続方法を確認できた対話サービスからも利用できる構成を想定していますが、dot の内部 API 連携や個人用 WeChat の自動送受信は未実装・未検証です。現段階では WeChat 専用画面の拡張を止め、再利用できる処理と接続の信頼性の検証を優先しています。

## 現在できること

- 模擬アダプターであることを明示した 2 種類のアシスタントで、個別の会話を作成できます。
- 模擬返信の逐次表示、タスクの進捗、状態の履歴を確認できます。
- タスクを中止したり、「計画の提示 → 確認待ち → 承認後に続行」というデモを試せます。
- ページの再読み込みやサービスの再起動後も、SQLite に保存した会話・メッセージ・タスクの記録を再表示できます。
- 架空の WeChat メッセージを受信箱に読み込み、プロジェクトごとの要件・期限・確認事項から元の文章をたどれます。
- 元の会話にひも付けた返信をプレビューし、明示的に送信を確定した後で模擬送信できます。成功・失敗・結果不明を確認でき、同じ送信要求を繰り返しても再送しません。
- 公式 Codex App Server で会話を継続し、ネイティブの承認要求を確認し、単発の承認・拒否を送信できます。中断や結果不明の状態は、公式の終態と履歴で照合します。
- 「运行动态」で実際の Codex タスクを一覧でき、状態・直近の活動・観察時間・承認待ちを確認できます。履歴はページ単位で読み込み、活動記録は最大 200 件の状態メタデータに限ります。
- AI、VPS、メッセージサービス、音声サービスの接続状況や今後の予定を確認できます。

模擬返信とプロジェクトの整理には固定のデモデータ・ルールを使います。大規模言語モデルは呼び出さず、サブスクリプションや API の利用枠も消費しません。プロジェクトとの関連付けは元メッセージ単位で保持し、1 つの会話が複数のプロジェクトに関わる場合も表現できます。AI による分類や、不確かな分類候補をユーザーが確定する機能は今後の対象です。

## 実際のサービスとの接続状況

| 対象 | v0.3 の状況 |
| --- | --- |
| Codex | 公式 App Server `0.162.1`・既存の ChatGPT ログイン・`gpt-6-astra` で、テキスト応答、同じスレッドの再開、実際のファイル承認要求の拒否と、明示的に許可されたテストファイルの単発書き込み、取消、SSE 再接続、結果不明のターンを履歴から復旧する流れを確認しました。旧 exec テキストモードも別アダプターとして残しています。書き込みはプロジェクト内の無害なテストファイル 1 件で確認し、検証後に削除しました。コマンド実行の承認は未検証です。 |
| Claude | 未接続です。検証環境に Claude Code はインストールしていません。 |
| WeChat・Slack・メール | 実際のメッセージの取得・送信は未接続です。受信箱は架空データとローカルの模擬送信のみです。 |
| dot API | 接続していません。利用可能な内部 API があることを前提にしていません。 |
| VPS・スマートフォンからの遠隔接続 | 未実装です。現在のサービスはローカルのループバックアドレスだけで待ち受けます。 |
| TTS・音声サービス | 未接続です。音声モデルや第三者の学習済み重みはダウンロード・実行していません。 |

デモの承認ボタンはローカルの模擬タスクを続行するためのものです。実際の Codex セッションには、この模擬承認フローを適用しません。CLI の設定やログイン状態だけでは、モデルへの接続成功やサブスクリプションの利用枠との互換性を保証できません。

## ローカルで起動する

Node.js **24.15 以降の 24 系、または 26 以降**が必要です。ネイティブの TypeScript 実行、SQLite、開発用依存パッケージを使用します。以下のコマンドはリポジトリのルートで実行してください。

```sh
npm ci
npm run build
npm start
```

既定の URL は **http://127.0.0.1:4317** です。待ち受け先はループバックアドレスに固定されているため、スマートフォンから直接アクセスすることはできません。データはプロジェクト内の `.data/relaydesk.sqlite` に保存され、このディレクトリは Git の管理対象外です。

開発モードでは次を実行します。

```sh
npm run dev
```

**http://127.0.0.1:5173** を開きます。Vite が API リクエストを `127.0.0.1:4317` に転送します。開発モードでは `PORT` を変更せず、既定の API ポートを使ってください。`npm start` で起動したサービスとは同時に実行しないでください。

## 模擬チャットを試す

アプリの UI は現在中国語です。以下は画面上の操作を日本語で説明しています。

1. 新しい会話を作成し、いずれかの模擬アシスタントを選びます。
2. メッセージを送り、タスクの開始から返信の逐次表示、完了までを確認します。
3. 承認デモを有効にし、タスクが確認待ちになったら承認またはキャンセルします。
4. ページを再読み込みして会話を開き直し、メッセージと状態が保存されていることを確認します。
5. `/fail` を送るとエラー表示を試せます。返信中のタスクはキャンセルできます。

## 業務メッセージの受信箱を試す

1. 業務受信箱を開き、架空のデモデータを読み込みます。連絡先・プロジェクト・メッセージはすべて架空のものです。再度読み込んでも送信記録は上書きしません。
2. プロジェクトごとの要件・期限・確認事項を確認し、対応する元メッセージを開きます。この整理は固定データによるデモで、実際の AI は使っていません。
3. 元メッセージを選び、返信を入力してプレビューします。アカウント、会話の識別子、引用元、返信全文を確認してください。内容を変更する場合は、プレビューを作り直します。
4. 模擬返信の送信ボタンを押したときに初めて送信が確定します。機密情報や影響の大きい操作を想定したデモでは、追加の確認が必要です。下書き、AI との相談、プロジェクトの整理だけで自動送信されることはありません。
5. デモ結果の選択肢を使い、成功・失敗・結果不明を試します。結果不明の場合は状態の照会だけを行い、確認できないまま再送しません。要求の識別子や本文を変更しても、送信結果が未確認の元メッセージに対する再送制限を回避することはできません。

これらの操作はローカルの SQLite に記録されるだけで、WeChat のメッセージを読み取ったり送信したりしません。リスク判定もデモ用のルールであり、機密情報や影響の大きい操作を網羅的に検出するものではありません。実際のメッセージイベントの受信、全文同期、リアルタイムの配信、画面ロック中の安定動作は未検証です。デスクトップのスクリーンショットだけでは、これらの機能が使えることは確認できません。実際の双方向接続には、安定した会話の識別子、公式に認められた接続方法、送信の権限を別途確認する必要があります。

## Codex App Server を明示的に有効にする

現在のネイティブ接続は、通常の公式ログインが済んだ CLI `0.162.1` を使用します。以下のモデルは今回確認したもので、すべてのアカウントで利用できるとは限りません。

```sh
RELAYDESK_ENABLE_CODEX_APP_SERVER=1 \
RELAYDESK_CODEX_PATH="$PWD/.tools/node_modules/.bin/codex" \
RELAYDESK_CODEX_MODEL="gpt-6-astra" \
npm start
```

既定では実行環境へのアクセスを無効にします。固定のテスト作業場所で承認を検証する場合は、ローカルの操作者が `RELAYDESK_CODEX_NATIVE_ENVIRONMENT=1` を追加できます。サンドボックスと単発のユーザー承認は維持します。既存 MCP は子プロセスの設定だけで無効化し、グローバル設定やログイン情報を変更しません。未知の結果は新しい入力を止め、保存済みの正確なターンを読むことで照合します。詳細は [ネイティブ接続の制限・起動・復旧](docs/native-driver.md)を参照してください。

## 実際のタスクの動きを見る

サイドバーの「运行动态」を開き、「进行中」または「历史任务」を選びます。この一覧は `codex-app-server` の実際の記録だけを表示します。プロジェクト欄は公式スレッドにひも付いたローカル作業場所を匿名化したもので、模擬受信箱のプロジェクトとは別です。まだスレッドにひも付いていないタスクは「未分组」と表示します。名前や入力文を転記せず、短いタスク ID で識別します。

「活动记录」で固定の状態ラベルと時刻を確認し、「打开会话」で元の会話の承認・停止・復旧操作に進みます。承認内容はそこで改めて確認します。接続が切れた場合は最後の記録を残し、新しいスナップショットを受け取るまで実行操作を止めます。60 秒以上活動が記録されなければ「暂无新活动」と表示しますが、経過時間だけで失敗や完了とは判断しません。表示する時間は接続や復旧待ちも含むローカルでの観察時間であり、モデルの正確な計算時間ではありません。

画面の「进行中」は最新 20 件を表示し、履歴は 20 件ずつ読み込みます。API の 1 ページは最大 50 件、タスクごとの活動記録は最大 200 件です。会話本文は従来どおり元の会話に保存されます。一覧のイベントには入力文、コマンド、ファイル差分、絶対パス、設定、非公開の推論を含めません。ブラウザーの再接続は現在の状態を読み取り、入力や承認を再実行しません。

## 旧 exec テキストモード

既定の起動設定では実際の AI を呼び出しません。公式 CLI で通常の ChatGPT ログインと利用可能なモデルを確認できた環境に限り、ローカルの操作者が有効にできます。検証では、明示的な承認を受けて公式 CLI をプロジェクト内にインストールしました。グローバルの CLI やログイン設定は変更していません。

この CLI をまだ導入していない環境で、インストールを行う場合のコマンドは次のとおりです。

```sh
npm install --prefix .tools --no-save --ignore-scripts @openai/codex@0.162.1
```

リポジトリのルートから、インストールした CLI の絶対パスを指定して起動します。以下のモデルは今回の検証で使ったものです。別の環境やアカウントでの利用可否は、個別に確認してください。

```sh
RELAYDESK_ENABLE_CODEX=1 \
RELAYDESK_CODEX_PATH="$PWD/.tools/node_modules/.bin/codex" \
RELAYDESK_CODEX_MODEL="gpt-6-astra" \
npm start
```

起動時に CLI のバージョンを上限時間付きで確認し、検証済みの `0.142.2` と `0.162.1` のみ受け付けます。新版では `agents.enabled=false` を追加し、`multi_agent` と `multi_agent_v2` も無効にします。未確認のバージョンは、制限設定の互換性を確認するまで起動を拒否します。

HTTP リクエストから実行ファイル、ディレクトリ、引数、モデル、環境変数を指定することはできません。アダプターは会話履歴を標準入力で渡し、毎回新しい一時的な CLI セッションを使います。作業ディレクトリは `.data/codex-workspace` に固定し、読み取り専用サンドボックスを指定して、シェル、プラグイン、ブラウザーなどの機能を無効にする設定を渡します。ログイン認証情報のコピーや、API キーへのフォールバックは行いません。ただし、読み取り専用設定と作業ディレクトリの固定だけでは、ファイルの読み取り範囲を完全には隔離できません。現状では信頼できるローカルの操作者向けであり、遠隔利用者や信頼できないメッセージサービスに直接公開できる構成ではありません。

CLI の JSONL 出力から、完成したアシスタントメッセージを受け取ります。実際のアダプターではトークン単位のストリーミングを保証しません。SSE はタスクの状態と受信済みのメッセージを継続して通知します。実際の Codex タスクは全会話を通じて同時に 1 件だけ実行し、競合した会話には後で再試行するよう表示します。キャンセル時は停止処理中として表示し、プロセスの終了を確認してからキャンセル済みにします。

サービスが異常終了した場合や、プロセスの停止を確認できない場合は、実際のアダプターを無効化し、再起動後もその状態を維持します。ローカルで以前の Codex プロセスが停止していることを確認したうえで、1 回の起動に限り `RELAYDESK_CODEX_ACK_INTERRUPTED=1` を追加すると解除できます。この値を起動環境に常設しないでください。保存された古い PID を使って自動的にプロセスを停止することはありません。データベースへの書き込みが失敗した場合はタスクを停止し、以後の書き込みを拒否します。ストレージの問題を解消してから再起動してください。

新しい CLI のインストールや再ログインには、利用者の明示的な承認が必要です。`.tools/` はプロジェクト内に公式 CLI を置く場合の保存先として使えますが、Git の管理対象外です。このリポジトリが CLI を自動インストール・更新したり、ログイン処理を行ったりすることはありません。互換性と制約の詳細は、[実サービスとの連携設計](docs/real-integration-design.md)と[検証記録](docs/verification.md)を参照してください。

## 検証

```sh
npm run check
```

TypeScript の型検査、ESLint、React DOM の操作テスト、バックエンドの結合テスト、CLI プロトコルのテスト、フロントエンドのビルドを実行します。

**2026 年 10 月 12 日の検証では、macOS・Node.js 26.3.0 で 126 件のテスト、型検査、lint、ビルドを確認しています。** ネイティブのプロトコル、承認の送信失敗、重複防止、早期取消、正確なターンの復旧、React DOM の操作も対象です。詳細な結果は検証記録に記載しています。

自動テストとは別に、公式 App Server を使い、HTTP/SSE のテキスト応答、実際のファイル承認要求の拒否と無変更、即時取消の `interrupted` 終態、同一スレッドでの文脈継続、サービス再起動後の `unknown → cancelled` 照合を確認しました。未知の入力や承認を自動で再送していません。追加の明示的な許可を受け、無害なテストファイルへの単発書き込みも確認し、内容を照合して削除しました。コマンド実行の承認、すべてのモデル・アカウント、常時稼働、WeChat、dot API、VPS 接続は未検証です。

ブラウザーがローカルページをブロックしたため、実ブラウザーでの操作やスマートフォン画面の見た目の検証は完了していません。jsdom のテストは、実ブラウザーでの表示確認を代替するものではありません。詳しくは[検証記録](docs/verification.md)を参照してください。
